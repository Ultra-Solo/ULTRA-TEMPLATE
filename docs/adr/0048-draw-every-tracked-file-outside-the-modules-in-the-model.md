# ADR-0048: Draw every tracked file outside the modules in the architecture model

**Status:** Proposed · Amends [ADR-0044](0044-model-the-repositorys-own-machinery.md) · Amends [ADR-0047](0047-draw-every-workflow-and-scripts-file-in-the-model.md) · **Date:** 2026-11-05

## Context

ADR-0046 drew the chassis scripts and ADR-0047 every file under `scripts/` and every workflow in `.github/workflows/`. About sixty tracked files were still outside the model: the root files (`AGENTS.md`, `README.md`, `package.json`, `.node-version`, `biome.jsonc`, the release-please configuration, the license and conduct pages), the `.github/` settings that shape CI and contribution (actionlint and zizmor audits, Dependabot, CODEOWNERS, the issue and pull request templates, the Copilot instructions, the reusable actions), the `.claude/` skills and settings that govern agent behavior, `.devcontainer/`, `data/plan.md` — the file that bounds what the self-upgrade gate may repair (ADR-0037) — the docs outside `docs/adr/`, the generator's own source in `template/`, and the chassis tests in `test/`. A change to any of them, weakening or deleting, fired no architecture rule: the model described the repository only where a previous ADR had drawn it, so the same drift those ADRs closed was still open everywhere else.

Three kinds of files stay out of the per-file discipline, each represented instead. The module directories (`services/`, `apps/`, `packages/`, `architecture/`) are drawn as one element each linking the module's README, held in both directions by `checkModel` (ADR-0044); a module's internal structure is its own boundary check's business (ADR-0005). The ADR record log `docs/adr/NNNN-*.md` cannot be linked file by file, because `template/clean.mjs` drops every record from a generated project, so a per-record link would fail there; the `adr` element links the two files that survive cleaning — the index `docs/adr/README.md` and the seed `0000-template.md` — and `scripts/check-docs.mjs` holds the records' grammar and the index. And `.template-provenance.json` exists only in generated projects — `template/init.mjs` writes it (ADR-0023) — so it is not template content and is never drawn.

## Decision

- `scripts/check-architecture.mjs` generalizes the ADR-0047 enumeration to the whole repository: `tree(".")` lists every tracked file (`git ls-files` in a work tree, so gitignored artifacts such as `scripts/safety-report.json` are not drawn; a disk walk outside one, skipping output directories and dot-directories other than `.github`, `.claude`, `.devcontainer`). `drawn(file, moduleDirs)` keeps every file outside the present module directories, outside `.template-provenance.json` (written only into generated projects, ADR-0023), and, of the ADR log, only the two seeds. `checkDrawn(files, links, all)` holds both directions over the whole tree: every drawn file is the target of some model link, and every model link — wherever it points — names a file that is here. `main` runs `checkModel` and `checkDrawn`.
- The second half of ADR-0044's checker rule — that every `README.md` link names a present module — is amended away, because ADR-0048's direction 2 now holds it strictly better repo-wide: a link to any file that is not tracked fails, README or not, and the first half (every present module has exactly one element linking its README) is unchanged. This is why the model can now link `docs/README.md`, `docs/adr/README.md`, `docs/knowledge/README.md`, `docs/knowledge/episodes/README.md` and `template/README.md`.
- `architecture/model/system.c4` draws the remaining files, with feature markers exactly where `template/features.json` owns the path, so a generated project keeps each link exactly when it keeps the file: a new `root` element (the root files; `biome.jsonc` behind the five features that own it, the release-please files behind `release`), a `github` element (the `.github/` settings and templates; the triage-and-fix prompt behind `knowledge`, the synthesis-architect agent file behind `template`), a `skills` element (`.claude/settings.json` and the ten skills, each feature-owned skill behind its feature), a `docs` element (`docs/` outside the ADR log; the devcontainer baseline behind `devcontainer`, the `docs/knowledge/` files on the existing `knowledge` element), a `tests` element (`test/`, with `check-architecture.test.mjs`, `check-contract.test.mjs`, `dev.test.mjs`, `check-facts.test.mjs`, `knowledge.test.mjs` behind their features), `.devcontainer/` on `environment` behind `devcontainer`, `data/plan.md` on `gate`, all of `template/` on `template` inside the existing `template` marker, the reusable actions on `ci`, and `docs/adr/README.md` on `adr`.
- `test/check-architecture.test.mjs` ships failing cases for both directions of `checkDrawn` and scope cases for `drawn`: a module's file is not drawn, an ADR record is not drawn, the seeds are.
- No change to `architecture/rules.mjs`: the new elements are `script`/`records` kind and satisfy the existing `undocumented`, `anchored` and `orphaned` rules by stating technology, description, links and a relationship.

## Alternatives considered

- **Draw the ADR records file by file behind the `template` marker.** Rejected: the marker strips `templateOnly` paths, and the records are dropped wholesale by `template/clean.mjs`, not listed in `features.json`; a per-record link would need a per-record marker the generator does not know. The index and seed links plus the `check-docs.mjs` grammar hold the log.
- **Draw module contents file by file.** Rejected: modules are one element with a README link by ADR-0044 and `checkModel`; their internals are held by each module's own boundary check (ADR-0005), and per-file links would couple every module change to the chassis model.
- **Enumerate the working tree, gitignored files included.** Rejected, as in ADR-0047: the model describes the repository, and git is the source of what is tracked.
- **Draw `.template-provenance.json`.** Rejected: only generated projects have it (ADR-0023), the template does not, so a link would fail in the template and the file in the project; the checker exempts it instead.

## Consequences

- Adding, renaming or deleting any tracked file outside the modules and the ADR record log without touching the model fails the architecture check in the same change's CI, in both directions; a model link to a file that is gone fails the same way.
- The `machinery` view now covers the whole repository surface: the rules, the settings, the skills, the docs, the tests, the generator's source, the dev container and the gate's plan.
- Generated projects keep the invariant automatically: a feature marker strips a link exactly when the feature's file is removed, and the check runs there against the generated tree.

## Enforcement

`node scripts/check-architecture.mjs model` (run from `architecture/`, named in `architecture/module.json`) fails when a tracked file outside the modules and the ADR record log is here but unlinked, or when any model link names no file here; `test/check-architecture.test.mjs` holds the failing cases for `checkDrawn` in both directions and the scope cases for `drawn`; `architecture/test/model.test.mjs` (`npm test` in `architecture/`) proves `anchored` and `orphaned` fire on the new elements.
