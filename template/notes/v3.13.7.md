## A security patch for one advisory

This patch closes [GHSA-834v-8h66-3h79](https://github.com/advisories/GHSA-834v-8h66-3h79) (CVE-2026-115895, high): `happy-dom` 21.0.3 turns an unsanitized import alias in its ECMAScript module compiler into host code execution when JavaScript evaluation is enabled and attacker-controlled module source is evaluated. Only `apps/web/package-lock.json` moves — 21.0.3 → 21.0.4, three lines: the version, the tarball and its integrity — because the manifest's `^21.0.1` already admits the fix, so an adopter whose lockfile has drifted can take the same fix with `npm update happy-dom` in `apps/web`.

The fix was proven, not assumed: the advisory's published PoC was run in a throwaway directory against both versions, and it reached the host filesystem on 21.0.3 while failing on 21.0.4. The 21.0.4 tarball's SHA-512 equals the registry's recorded integrity and `npm audit signatures` verified every package's signature; the release was published three days before the advisory and its entire diff is the two security fixes, so this is a studied patch, not a hot one.

The template's own tests are not a reachability path: `happy-dom` is a devDependency, used by one component test that renders a trusted fixture with `fetch` stubbed, and `enableJavaScriptEvaluation` appears nowhere in the repository. An adopter becomes exposed only by using happy-dom beyond the dev-test role, with JavaScript evaluation enabled and untrusted module source. The template version advances to **v3.13.7**.
