## Reproducible Python image security fixes

The Python runtime retains its pinned base digest and applies four checksum-locked Debian security packages. All eight base architectures have reviewed package identity and SHA-256 inputs. The Docker build does not use changing apt indexes; every payload is verified before installation, and a newer base is never downgraded. An unavailable or changed pool file fails clearly until its lock is refreshed or a fixed vendor base replaces the patch.

On the recorded Linux/amd64 baseline and vulnerability database, fixable high/critical findings decreased from seven package occurrences across CVE-2026-103111, CVE-2026-75804 and CVE-2026-84782 to zero. This does not mean the image is vulnerability-free, and does not clear the separate development-container findings.

The required `verify` gate now includes native amd64 and arm64 Python image jobs. Both exercise the real image's full HTTP contract, receive deadlines and shutdown, retain complete Trivy JSON artifacts, and fail on fixable high/critical runtime findings. This stricter verification policy makes the release **v3.1.0**. A managed build proxy can use the optional `proxy_ca` public CA build secret; TLS remains verified and the certificate is not copied into image layers.

`node scripts/probe-image.mjs py-service --full-contract` runs the extended container contract; existing probes retain their startup/default checks. See the Python module's README for the lock update procedure. Keep the v3 exact-source provenance record when upgrading so this repair can reach generated projects through their verified baseline.
