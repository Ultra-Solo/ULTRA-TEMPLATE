## A new mutation gate for large edits

This release adds `scripts/check-safety.mjs`, a diff-aware gate that rejects any single change which silently removes a large part of the repository. It is triggered before anything is committed and again in CI, and it is the safeguard the release plan's standing ledger leaves open for later — A1 in ADR-0025, "guard against a single agent silently erasing a large part of the codebase in one pass."

The gate compares the commit being reviewed against whatever has been staged since, and rejects any modified file that loses more than 30% of its non-blank lines and more than 25 lines in one change, unless a compensating rewrite is in progress — additions that make up at least 20% of the file. Deletions between 20% and 30% of the file produce a soft warning rather than a failure. Whole-file deletions are reported as plain changes, not rejections: deleting a file is visible in `git status` and goes through the pull request like anything else.

Two rules are important for anyone who edits this template:

- The thresholds are repository invariants, not tuning knobs. Changing them breaks the invariant, not the implementation, so treat any request to move them as a candidate for a new ADR rather than a patch.
- The gate runs only against tracked text files. Build artifacts, dependency directories, the `node_modules` tree, and binary or generated content are not subject to it; a file whose line count collapses because a dependency was removed is counted against the original file, not the result.

The gate can be installed locally as a pre-commit hook with `cp scripts/hooks/check-safety .git/hooks/pre-commit && chmod +x .git/hooks/pre-commit`. A machine-readable copy of each run is written to `scripts/safety-report.json`, which this release adds to `.gitignore`. The gate is pure Node stdlib — no npm dependencies and no external subprocesses — so it can be reviewed and copied into another repository unchanged.

Install the hook and let the gate run green before relying on it; the first review against a large existing feature branch will produce the highest rejection counts. The template version advances to **v3.14.0**.
