## Configuration cases get their own port

`check-contract` starts each task service once per configuration value, in a concurrent pool, and each case used to ask the kernel for a free ephemeral port. A Linux kernel reissues a port it just freed to the next `bind(0)` call, so two workers could be handed the same port, and the service binding second exited with `EADDRINUSE` — about one run in thirty, and only in CI: no available local kernel held the port long enough to show it. The first in-container verify on main caught it. Each case now takes its own slot of eight candidate ports starting below the ephemeral range, where the kernel never allocates, and says so clearly when a slot is full. The template version advances to **v3.4.0**.

## Publication is gated on verify

A template release now publishes only after the `verify` workflow has passed on a push to main, and the release names the exact commit verify passed — not the branch head, which can have moved. A version that is already released is a no-op, so a re-run or a green verify that changes no version publishes nothing. For a project made from the template this changes nothing to merge; it changes what taking a release guarantees: a tag now always names source that passed every check.

## The devcontainer scan records what it actually scanned

The scan's metadata step derived its base-image digest from a hardcoded pin and recorded the built image's repo digest — which is always empty, because a locally built image has none. It now reads the base image from the Dockerfile's own `FROM` line, records the built image's ID as its identity, and adds the scanner's version and the source commit, so a summary row says exactly which commit and which scanner produced the evidence.

## The scan baseline, triaged

The report-only gate counts 378 fixable high or critical findings, and the number meant nothing to anyone who had not read the report. `docs/devcontainer-scan-baseline.md` records what they are: 93.6% sit in `linux-libc-dev`, Ubuntu's kernel headers — compile-time material that attracts every kernel CVE because it ships the kernel's source metadata — and the page says which findings are the signal (the packages the image actually runs) and which follow the base image digest. Projects generated with the devcontainer feature get the page.
