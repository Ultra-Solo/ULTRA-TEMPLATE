## v3.16.0 was never published; this release carries it

`verify` on the v3.16.0 commit was cancelled when its Windows job reached the 15-minute limit, and a release publishes only on a passing run, so no `v3.16.0` tag exists. Updating from v3.15.2 lands on v3.16.1, and these notes are the notes for both. The Windows chassis job's limit is now 25 minutes, because the second brain added about 3 to 5 minutes there (6.6 before, 9.8 to 11.4 after); a project's own `verify.yml` gets the same limit.

### The second brain (from v3.16.0)

Every preset, `minimal` included, now ships `docs/knowledge/`: a generated briefing, a deterministic graph of the repository, an optional sealed import of an LLM-inferred graph, and human-written episodes. `node scripts/knowledge.mjs` offers `sync`, `check`, `query`, `path`, `explain`, `stats`, `import-graphify`, `export` and `unstaged`. See [ADR-0038](../../docs/adr/0038-keep-a-layered-self-checking-memory-in-docs-knowledge.md).

What can turn your build red:

- `verify` gains `chassis: knowledge`, which runs `check`. After changing docs, scripts, workflows, modules or ADRs, run `node scripts/knowledge.mjs sync` and commit the result; a stale file, a source the graph lacks, a dangling episode reference or an edited committed episode fails.
- `test/knowledge.test.mjs` joins the chassis tests.

Files an update may conflict on: `AGENTS.md`, `docs/README.md`, `.gitignore` and `.gitattributes` (each gains a `knowledge` block), and `scripts/verify.mjs` (one guarded step). `docs/knowledge/graph.json` and `README.md` are generated: on conflict, take either side and run `sync`.

Nothing is installed: the engine is dependency-free Node. graphify is optional and only feeds L3. No bot or agent writes to the repository, and no command writes an episode. The immutability check compares against HEAD or `KNOWLEDGE_BASE_REF`, so in a pull request's merge commit it needs that variable to see a change.

### Three gaps in the second brain's hook and graphify import are closed

Review of v3.16.0 found three defects in `scripts/knowledge/`. Each was reproduced with a test that failed on v3.16.0 and passes now.

- **`unstaged` ignored deletions.** A tracked source deleted from the working tree but not yet staged was dropped from the list, so the pre-commit hook could stage a graph that no longer listed a file the commit still contained. It is now listed, and the hook refuses.
- **`import-graphify` accepted characters `verify` refuses.** Its sanitizer missed the Unicode tag block, variation selectors and the Hangul and Halfwidth fillers that `scripts/check-hygiene.mjs` rejects, so an import could pass and then turn the next `verify` red. It now strips the same set.
- **An edge's cited file was discarded without a line number.** The evidence fell back to the `from` node's file, so the file the edge actually cites was left out of the hashes that seal the import. The cited file is kept, at line 1 when no line is given.

Nothing to do after updating, except that an import made with v3.16.0 and rejected by `verify` can be imported again. The README now describes the hook and `unstaged`. Files an update may conflict on: `README.md`, inside its `knowledge` block.
