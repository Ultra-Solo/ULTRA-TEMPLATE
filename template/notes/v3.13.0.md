## A release-cadence agent joins the synthesis architect

The repository gains a second governed agent adapter, `release-cadence`, selected by name from `.github/agents/` the way [ADR-0009](../../docs/adr/0009-where-agent-adapters-and-skills-live.md) governs every agent adapter, and deferring to [AGENTS.md](../../AGENTS.md). It wraps one procedure — deciding and executing the next release — and nothing else.

The decision half is threshold arbitration, the discipline this template's own releases are run by: the standing plan and its trigger table are the prior, and re-deriving an unchanged plan is a failure mode; predictions are pre-registered with Brier scoring before any state is checked; only elapsed trigger windows are checked, from raw sources named as opened; the cheapest reversible experiment runs instead of argument; every live path including doing nothing is priced in numbers; the ledger is scored before predicting again; and a trigger at its threshold executes its pre-made response — the threshold decides, not the narrator.

The execution half carries the release discipline end to end: sync before starting, pre-flight every hand-pinned tool against its live source before scoping the release's content, version by the table, hunt the coupled copies a moved fact drags, run the whole validation battery with the pinned tools on PATH, watch CI to completion, verify the release from the published tag with a project generated from it, and finish the records — a release is done when the records say so.

Generated projects inherit the agent through `init.mjs`, like every file under `.github/agents/`. The hand-pinned toolchain is current from v3.11.1, so no tool pin moves in this release. The template version advances to **v3.13.0**.
