## Exact-source generation and updates

Initialization now resolves the stable published release named by the copied template's manifest and generates from its upstream commit. A missing or failed publication stops before project files change. A GitHub template copy's own history is never treated as upstream history.

Every new project records `.template-provenance.json` schema 1: canonical upstream, version, resolved commit, release tag (or null for an explicit local source), original identity, selected features, description and copyright year. Commit this file. The updater reconstructs the recorded commit with those inputs and rejects repointed tags, missing objects and malformed records before executing either initializer, even for an already-current update.

This is a **major compatibility change**. Default initialization needs network access and a stable GitHub release. For offline generation, use a trusted local Git mirror with the release tag (`--source <path>`), or pass `--source <path> --source-commit <full-sha>` for an explicitly unreleased snapshot. Local source generation records its commit and does not claim a published release. Never pass a generated repository's HEAD as the upstream source.

Legacy projects keep their CHANGELOG origin reader, but updating with the new script requires `--legacy-commit <full-sha>` after reviewing the original tagged generation baseline. A version-only record cannot prove which source produced a project created from main during earlier drift. Such a project needs a reviewed repair; the script cannot discover its missing history. An old generated project's updater must first be replaced with this release's `scripts/template-update.mjs` and `scripts/template-source.mjs`; commit those two files, then run the migration with the reviewed baseline SHA and inspect the result.

Original identity inputs remain the reconstruction inputs after a repository or package rename. Custom descriptions, adopter edits and the original copyright year are preserved. Feature changes advance the provenance selection alongside the human-readable CHANGELOG entry. `--to-commit <full-sha>` optionally pins an expected target release commit.

Commit verification identifies source and detects later tag changes; it does not independently authenticate the publisher, sandbox initializer code, or prove a legacy baseline. Review and trust the upstream or explicitly selected local mirror.
