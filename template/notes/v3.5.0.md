## One command starts the development stack

`node scripts/dev.mjs` starts the task service and every module that runs alongside it, waits until each answers, streams their output with a prefix, and stops them all as one tree. A module runs in development when its `module.json` carries a `dev` key naming the command; the web app and every task service have one, so the stack a project gets is the stack it has. When several task services are present, `--api <id>` picks the one to start. The template version advances to **v3.5.0**.

## The doctor reports what a checkout needs

`node scripts/doctor.mjs` reports, as JSON and without changing anything, what the checkout needs before its checks can run: the Node pin, git and the working tree's state, each module's toolchain, files and installed dependencies, the pinned tools, and the template a project came from. It works offline. What the machine cannot decide is reported as `unknown`, never as a silent pass, and the exit code says which: 0 nothing failed, 1 something failed, 2 the doctor itself could not run.

## `--check` asks about updates without taking them

`node scripts/template-update.mjs --check` reports as JSON the release a project is on, the newest one the template has, and the command that would move the project to it, and exits 1 when a newer release exists — so a script can ask without parsing the report. It only reads, so it works on a dirty tree, and it takes no other option but `--template`.
