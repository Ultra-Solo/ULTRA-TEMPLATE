## The refresh, folded into one path

This patch lands the two open dependency bumps in one commit rather than merging them one at a time against a base each has already missed. The first is `github/codeql-action` v4.38.3 → v4.39.0, at its three usages — `init` and `analyze` in `codeql.yml`, `upload-sarif` in `scorecard.yml` — moved together so the action stays pinned at one SHA everywhere. The release raises the minimum CodeQL bundle to 2.20.7, which this repository does not pin against: no `tools:` input is set, so every run already resolves the current bundle. The same release validates the `analyze` step's `checkout_path` input, fixes cache restoration with third-party caching implementations, and aligns `start-proxy`'s release lookup with `init`'s.

The second is the Go service's runtime base: `gcr.io/distroless/static-debian13:nonroot` moves to the image build the registry now serves under that tag, digest `e2e927ec…` → `18f4cc26…`, as Dependabot resolved it. The tag is unchanged, so nothing about the image's contract moves — only the Debian package set under it. The digest is pinned, and the container-image probes that exercise the built image run in CI's `py-image-security` and chassis jobs.

Neither bump closes an advisory; both are freshness, the same character as the v3.13.3 refresh. Dependabot opens these as two pull requests that each arrive after the other's base has moved on, so each alone fails `template-release-check` — the batch is the path the cadence already uses when that happens. The template version advances to **v3.13.8**.
