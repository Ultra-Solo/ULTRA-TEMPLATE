## `setup` no longer points at a `verify` that cannot run yet

In a project that has never been committed to, `node scripts/setup.mjs` ended with `setup: OK — next, node scripts/verify.mjs`. `verify` measures the change against `HEAD` (`check-safety`), and a repository with no commit has none, so following the signpost reached the failure v3.15.1 made readable. `init` and the README already say install, commit, then verify; `setup` was the one place that still skipped the commit.

- `scripts/setup.mjs` checks whether `HEAD` exists. With none, it ends with `next, commit, then verify: git add -A && git commit -m "chore: initialize project" && node scripts/verify.mjs`; with one, the line is unchanged.
- `test/setup.test.mjs` runs `setup` in a throwaway repository, once before and once after its first commit. The first case fails on v3.16.1.
- The README's `scripts/` entry in *What's here* now names `check-safety.mjs`, `check-plan.mjs`, `tools.mjs` and `template-update.mjs`, which earlier releases added without listing.

Nothing needs installing. The template version advances to **v3.16.2**.
