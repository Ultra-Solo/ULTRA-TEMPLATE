This release collects the changes after v2.0.1 under a new baseline. The task services' development servers now bound total header and request receive time, including clients that periodically trickle bytes. Timed-out requests may receive a server-specific response or have their connection closed; production WSGI deployments must configure equivalent receive deadlines. The Python deadline-wrapped input is closed correctly, and short reads are refused. Review these timeout behaviors when upgrading an HTTP service.

Pinned-tool downloads retry transient HTTP failures while retaining checksum verification. Node type pins and module install instructions have been updated. Changes to customized service composition roots, API contract files, and corresponding documentation may need manual conflict resolution during an update.

For template maintainers, the required `verify` gate now rejects generated-output changes that reuse the previous template version. Dependency PRs that affect generated projects need a version bump or inclusion in a release PR. This check is removed during initialization.

Template publication is asynchronous. Confirm the release before initializing or updating from its version; use the published tag's source for a known baseline. Projects generated from main after v2.0.1 but before this release may already contain some of these changes while recording v2.0.1. Review the update's dry run and resulting diff carefully; no exact old source can be inferred from that origin line alone.
