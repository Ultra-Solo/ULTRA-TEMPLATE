## Dev Container lifecycle and in-container verification

The `devcontainer-scan` workflow now exercises the Dev Container lifecycle, not only the image: after building and scanning the image, it runs `devcontainer up`, which applies the configuration and runs `postCreateCommand` — installing the pinned tools and every module's dependencies — and then runs `node scripts/verify.mjs --no-chassis` inside the container through `devcontainer exec`, so every module's checks are proven to pass in the environment a contributor actually uses. The container is labelled and removed by a trap on step exit, whether the step succeeds or fails.

Checks that cannot run inside the container are reported as skipped by name, as they are locally. The template version advances to **v3.3.0**.
