This release holds the three task services to one way of reading a request and answering it, makes a
move safe when two arrive at once, and proves each pin before anything depends on it
([ADR-0017](https://github.com/hynix666/ULTRA-TEMPLATE/blob/v2.0.0/docs/adr/0017-prove-the-supply-chain-before-it-runs.md),
[ADR-0018](https://github.com/hynix666/ULTRA-TEMPLATE/blob/v2.0.0/docs/adr/0018-every-task-service-reads-and-answers-alike.md),
[ADR-0019](https://github.com/hynix666/ULTRA-TEMPLATE/blob/v2.0.0/docs/adr/0019-moves-are-compare-and-set-on-the-store.md)).
No feature, preset, flag or origin line changed: update as usual.

### The one breaking change: every store implements a replace

Two moves at once could both be made, because a move read the task and then saved it. The storage port
of each task service now has a compare-and-set replace, and a move uses it instead of saving:

- **Go:** `Replace(ctx, task, prev entity.Task) error` on `usecase.TaskRepository`, returning `usecase.ErrStale` when the stored task is no longer `prev`, and `entity.ErrNotFound` when there is none.
- **TypeScript and Python:** `replace(task, prev)` on `TaskRepository`, resolving or returning `false` when the stored task is no longer `prev` or there is none.

The memory stores implement it. **A store you wrote does not compile (Go) or type-check (TypeScript, Python) until it does.** In a database it is one conditional statement:

```sql
UPDATE tasks SET title = $1, status = $2, updated_at = $3
 WHERE id = $4 AND title = $5 AND status = $6 AND created_at = $7 AND updated_at = $8
```

Report stale when it changed no row and the task exists, and not found when it does not. Then run the conformance suite against your store (`repotest.Run`, `checkTaskRepository`, `check_task_repository`): its four new cases include sixteen replaces at once from one version, of which exactly one may be made.

### Checks that can now turn your build red

- **The contract** holds every JSON answer to the OpenAPI schema for its status, and adds cases a service you changed on your own may meet:
  - a body that is not UTF-8, has a byte-order mark, or uses `NaN` is 400; so is a field spelled with other capitals, or a status that is not a string;
  - a title is trimmed of exactly the Unicode `White_Space` property (`titleWhitespace` in `scripts/rules/task-rules.json`);
  - a time is UTC to the millisecond, and the list is oldest first;
  - a 405 carries `Allow`;
  - sixteen moves at once: one 200, fifteen 409;
  - shutdown: with a request half sent, SIGTERM must leave the service up to answer it and exit 0, or exit 1 once the shortest `SHUTDOWN_TIMEOUT` has passed.
- **check-facts:** the MCP server states `titleWhitespace`, and the web app no longer states `maxTitleLength`.
- **Hygiene rule 13** also fails a `verify.yml` module job whose module is not present.
- **Hygiene rule 14** also fails a Dev Container `image` without a digest.
- **Hygiene rule 16** fails a setup action that a tool in `tools.json` lists under `actions`, such as `astral-sh/setup-uv`.
- **Hygiene rule 19** is new: one SHA per action across workflows and local actions, and every directory holding an `action.yml` listed in Dependabot's github-actions entry.
- **zizmor's `dependabot-cooldown` audit** is on again: every Dependabot entry needs a `cooldown`.
- **check-docs rule 12** is new: an ADR that amends or supersedes another is named on that record's status line too.
- **verify** fails a chassis tool that is missing in CI, where it used to skip it.
- **The `secrets` job** is new in the gate: gitleaks over the commits each change adds. Silence a false positive in `.gitleaksignore`, as `SECURITY.md` says.

### Where an update is likely to conflict

- **The services' routers and HTTP adapters, `main` files, ports, use cases, memory stores and conformance suites:** a body is read, a 405 answered and a move made differently.
- **`.github/workflows/verify.yml`:** the `actionlint` job is gone (the `chassis` job runs it through verify), and the `secrets` job is new.
- **`.github/dependabot.yml`:** the github-actions entry lists `directories`, and every entry has a `cooldown`.
- **`.github/actions/module/action.yml`, `template-test.yml`, `copilot-setup-steps.yml`, `security.yml`:** setup-uv is gone.
- **`.devcontainer/`:** the image moves into a `Dockerfile`, by digest.
- **ADR status lines and `docs/adr/README.md`:** records now name what amended them.
- **The module READMEs:** their check lists are generated blocks now; run `node scripts/generate-docs.mjs`.
- **`AGENTS.md`**, and the add-endpoint and change-task-contract skills.
