## A generated project's first check run reports a verdict

A project generated from this template, used exactly as the instructions it printed said to use it — `git init -b main && git add -A`, then `node scripts/setup.mjs`, then `node scripts/verify.mjs` — ended in a stack trace instead of a verdict:

```
Error: git rev-parse HEAD exited with 128
```

`chassis: check-safety` measures the change under review against `HEAD`, and a repository that has never been committed to has no `HEAD` to resolve: `git rev-parse HEAD` exits 128 on an unborn branch. That call sat above the guard that reports a repository with nothing tracked yet, so the guard's message — telling the reader to run `git add -A`, the step they had just run — was unreachable in the only state that reached it. Every project generated since v3.14.0, when `check-safety` landed, was told to run its first check in that state.

Three changes, and the code is the smallest of them.

- `scripts/check-safety.mjs` resolves the "nothing is tracked yet" guard first, and resolves `HEAD` defensively. An unborn branch now fails with a sentence that names the remedy — `no commit yet — this gate measures the change against HEAD, so commit the files first: git add -A && git commit -m "chore: initialize project"` — instead of throwing. The `git diff` calls below it were already written that way; the `HEAD` lookup was the one that was not.
- The instructions that create the state are in order: install, then `git add -A && git commit -m "chore: initialize project"`, then verify. That is the block `template/init.mjs` prints at the end of generation, in both its local and its published-release path; [README.md](../../README.md) step 4; and the recipe in [template/README.md](../README.md) that verifies a template change. All three already carried the commit step; all three printed it after the `verify` it is a precondition for.
- `test/check-safety.test.mjs` gains the case that would have caught it — files added, nothing committed — and `template/init.test.mjs` asserts that the steps init prints commit before they verify. Both fail on the code before this release.

The gate still fails on an unborn branch rather than passing. A check that could not run is a failure to report, and a gate that skipped itself whenever `HEAD` was missing could be silenced by deleting the branch it measures against.

Nothing needs installing, and no generated project needs a change beyond its next update. The template version advances to **v3.15.1**.
