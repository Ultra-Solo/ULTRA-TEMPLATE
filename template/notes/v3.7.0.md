## The MCP server speaks Streamable HTTP beside stdio

The MCP server now serves its four task tools over either transport, chosen at startup: stdio, the default, exactly as before, or Streamable HTTP with `MCP_TRANSPORT=http`, which answers `POST /mcp` on `MCP_HTTP_PORT` (default 3000; `0` asks the operating system for one). A client that cannot spawn a subprocess — a hosted assistant, a web client — can now reach the server at a URL, and the same image serves both forms. The HTTP endpoint is stateless, with no session and no authentication, so a deployment that exposes it beyond localhost fronts it with a proxy that authenticates; the registry manifest keeps advertising the stdio form any registry client can start. Nothing is written to stdout on either transport, the tests drive the HTTP form through the SDK's client over a real socket, and the e2e walk runs every tool over both ([ADR-0030](../../docs/adr/0030-serve-mcp-over-streamable-http-beside-stdio.md)). The SDK floor rises to 2.3.1, where the stateless handler lives. The template version advances to **v3.7.0**.
