## The cadence agent's first corrections, and clean audits

The release-cadence agent that shipped in v3.13.0 drew a review with five findings; this patch corrects all five in the released file. The cadence check now scores the ledger before registering new predictions, so calibration is measured before it is claimed. Release execution commits the candidate before the checks that read committed refs, and the battery it runs is the repository's own — the template's full battery here, a generated project's verify job there, where `template/` does not exist. The merge step now knows both release paths: this repository's tag, and a generated project's release-please pull request, which alone creates the tag. Two grounding rules that restated [AGENTS.md](../../AGENTS.md) are dropped; the deferral at the top of the file already carries them.

The default publication check no longer depends on a shared runner's IP reputation: the template-release-check job passes the workflow's own token as `GH_TOKEN`, and `init.mjs`'s bootstrap fetch sends it as a Bearer header when one is present. Unauthenticated local use is unchanged — no token, no header. This is the durable fix for the intermittent 403s that check has drawn on shared runners.

The audits run clean. In `architecture`, `vite` moves 8.3.0 → 8.3.4 to match `apps/web`, carrying its rolldown and oxc toolchain with it, and `vite-plugin-singlefile` 2.3.3 → 2.3.4 drops the vulnerable `braces` chain behind it; `npm audit` now reports no findings in any module. In `services/api-py`, `uv lock --upgrade` recovers six updates Dependabot cannot propose — its hosted `uv` cannot satisfy the `required-version` this project declares — among them `mypy` 2.3.1 → 2.4.0 and `ruff` 0.16.9 → 0.17.1, every one within the declared specifiers and passing the service's battery. The hand-pinned toolchain is current against every live source; no pin moves. The template version advances to **v3.13.1**.
